Lesson 1 — What is HTTP?

HTTP stands for Hypertext Transfer Protocol. It is a set of rules that lets a client—such as a browser or C# application—ask a server for something and receive a response.

Core idea: request → server processes it → response.

Analogy: ordering at a restaurant

You = clientThe person or application asking for something.
Your order = HTTP requestSpecifies what you want the server to do or return.
The kitchen = serverProcesses the request, perhaps by running code or querying a database.
Your meal = HTTP responseThe result, such as a webpage, data, confirmation, or error.

The request-and-response cycle

1
You request something.
A browser asks for a webpage, or an application asks for production data.
2
The request reaches the server.
HTTP defines the format and meaning of the request.
3
The server does its work.
It might return a file, execute application logic, or retrieve data from a database.
4
The server sends a response.
The response includes a status code and may include a body containing HTML, JSON, or other data.

HTTP does not itself run your C# code or query your database. It defines how the client and server communicate.

Lesson 2 — HTTP vs HTTPS

A protocol is an agreed set of communication rules. HTTP is the protocol used for web requests and responses. HTTPS is HTTP protected by TLS encryption and authentication.

HTTPHTTPS
HTTP itself does not encrypt the connection.TLS helps protect data in transit from being read or changed by others.
Not suitable by itself for sensitive traffic over untrusted networks.The normal choice for modern websites and APIs.
Often shown with http://Often shown with https://
Remember: HTTPS helps protect the connection, but it does not prove that a website's owner is honest or that its content is safe.

Analogy: HTTP is like sending a postcard that someone handling it might read. HTTPS is more like putting the message inside a locked, tamper-protected case that only the intended endpoint can unlock.

Lesson 3 — What is inside an HTTP request?

Suppose your browser visits https://example.com/products. A simplified HTTP request might look like this:

GET /products HTTP/1.1 Host: example.com Accept: application/json

What each line means:

  • GET is the method: the type of operation being requested.
  • /products is the path: the resource being requested.
  • HTTP/1.1 identifies the HTTP version in this example.
  • Host identifies the website host.
  • Accept tells the server which response formats the client can handle.

Requests can also contain a body. For example, a POST request might send a JSON object with form data. Headers provide additional information about the request or response.

This is a simplified example. Real browser requests often contain more headers, and HTTPS encrypts HTTP details while they travel over the network.

Lesson 4 — Methods and status codes

Common HTTP methods

GET

Retrieve a resource. Example: fetch a list of coils.

POST

Submit data or initiate an operation. Example: submit a production report.

PUT

Create or replace a resource. Example: replace a full record.

PATCH

Update part of a resource. Example: change one field in a record.

DELETE

Request removal of a resource.

These methods communicate intent. The server's application code determines how it handles the request.

Common response status codes

Lesson 5 — Using HTTP from C#

A C# application can use HttpClient to send requests to a web API. This example retrieves a sample post from a public test API.

using System; using System.Net.Http; using System.Threading.Tasks; class Program { static async Task Main() { using HttpClient client = new HttpClient(); string url = "https://jsonplaceholder.typicode.com/posts/1"; HttpResponseMessage response = await client.GetAsync(url); response.EnsureSuccessStatusCode(); string data = await response.Content.ReadAsStringAsync(); Console.WriteLine(data); } }

Understand the key lines

  • HttpClient sends HTTP requests.
  • GetAsync(url) sends a GET request asynchronously.
  • await lets the method asynchronously wait for the operation to finish without blocking the thread in the usual synchronous way.
  • EnsureSuccessStatusCode() throws an exception if the response status is not successful.
  • ReadAsStringAsync() reads the response body as text. Here, the text is JSON.
Try it: Run the example in a C# console project with internet access. The API returns JSON for a sample post. In a real application, also consider cancellation, timeouts, exception handling, and reusing HttpClient appropriately.

How this relates to a plant application

A web dashboard could send an HTTP request to an API for coil or production data. The API might query Oracle or SQL Server, then return JSON to the dashboard. HTTP carries the request and response; it does not replace the API or database.

Lesson 6 — HTTP vs TCP/IP

HTTP is only one part of network communication. Different technologies have different responsibilities.

IP — addressing and routingLike the address and route used to get a package toward its destination.
TCP — reliable deliveryLike a delivery service that aims to deliver data reliably and in order.
HTTP — application conversationLike the instructions describing what the sender is asking for and what the response means.
TLS — connection securityHelps encrypt data and authenticate the server for HTTPS connections.
TechnologyMain responsibility
IPAddressing and routing packets across networks
TCPReliable, ordered byte-stream delivery
HTTPRules for web requests and responses
TLSEncryption and authentication for a secure connection

HTTP/1.1 and HTTP/2 typically use TCP, with TLS for HTTPS. HTTP/3 uses QUIC, which runs over UDP.
